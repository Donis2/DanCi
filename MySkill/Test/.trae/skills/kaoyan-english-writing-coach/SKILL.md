# 考研英语写作批改辅导

## 何时调用此 Skill

当用户出现以下场景时调用：

1. 用户发送了一段英文短文（或句子、小故事），并提到希望批改、润色、检查语法
2. 用户提到"考研单词""背诵单词""用今天背的词写""改作文""批改"等关键词
3. 用户希望把基础词汇替换成考研高级词汇
4. 用户从单词背诵网站导出了 Markdown 单词表，希望基于这些单词检查写作

**不要调用的场景：**

- 用户只是问单词含义，没写短文
- 用户写的短文与考研英语无关（如日常聊天、技术文档）

## 路径约定（相对路径，跨项目通用）

本 skill 位于 `<项目根>/.trae/skills/kaoyan-english-writing-coach/SKILL.md`。

从 SKILL.md 出发：
- 项目根目录 = `../../..`（往上走 3 层）
- 单词表 = `<项目根>/words/words.md`
- 输出目录 = `<项目根>/output/`
- 词汇查询脚本 = `<项目根>/.trae/skills/kaoyan-english-writing-coach/scripts/query_vocab.py`
- 考研大纲词汇数据 = `<项目根>/.trae/skills/kaoyan-english-writing-coach/考研英语大纲词汇.xlsx`

**执行时**：用工具调用时，路径要拼接成绝对路径。可以在 skill 加载时通过 cwd 推断项目根，或让 agent 用 LS 工具确认项目根位置。

## 工作流

### Step 1: 确定项目根路径

agent 在执行前，先通过当前工作目录（cwd）或 LS 工具确认项目根目录。项目根的标志是：存在 `.trae/skills/kaoyan-english-writing-coach/SKILL.md` 这个文件。

确定项目根后，所有路径基于项目根拼接。

### Step 2: 读取单词表

**必须先读取**：`<项目根>/words/words.md`

用 Read 工具读取该文件。文件内容是从单词背诵网站导出的 Markdown 表格，格式如下：

```markdown
# 今日学习的单词（2026-07-28）

共 50 个新词

| 序号 | 单词 | 词性 | 词频排名 | 真题出现次数 | 释义 | 其他拼写 | 分类 | 熟练度 |
|------|------|------|----------|--------------|------|----------|------|--------|
| 1 | the | art. | #1 | 10151 | the art.这(那)个;这(那)些 | - | 抽象概念/基础功能词 | 完全记住 |
...
```

**如果文件不存在或为空**：告诉用户先从网站导出单词表，保存到 `<项目根>/words/words.md`，然后重新发送短文。

### Step 3: 接收用户短文

用户在对话中只发送英文短文（不需要再粘贴单词表）。短文可能包含：
- 英文句子
- 中文夹英文（不会的词用中文写）
- 中文专有名词（地名/人名/身份）

### Step 4: 执行批改（分两次输出）

#### 第一次输出：错误修改 + 单词检查

按"批改提示词"执行第一部分工作：
1. 逐句纠错
2. 单词用法检查

**输出到文件**：用 Write 工具把结果写入：
`<项目根>/output/批改结果_错误修改_<YYYY-MM-DD>.md`

文件内容格式：

```markdown
# 错误与修改建议 + 单词使用检查

**批改日期**：YYYY-MM-DD HH:MM
**单词表来源**：words/words.md

---

## 一、错误与修改建议

### 1. 原句：xxx
**修改**：xxx
**解释**：xxx

### 2. ...

---

## 二、单词使用检查

| 单词 | 状态 | 用法提示 |
|------|------|----------|
| appropriate | ✓ 正确使用 | 常见搭配：be appropriate for/to |
| significant | ✗ 使用错误 | 注意：作形容词修饰名词，不作副词 |
| ... | 未使用 | 建议：可用于表达"重要的" |
```

写完文件后，在对话中告诉用户：
- 文件已生成路径
- 简要总结（共发现 X 处错误，Y 个单词正确使用，Z 个使用错误，W 个未使用）
- 提示用户："回复'继续'，我将生成润色版全文和双语对照版"

**等待用户回复"继续"**，不要继续输出。

#### 第二次输出：润色全文 + 双语对照

用户回复"继续"后，按"批改提示词"执行第二部分工作：
3. 连贯性润色
4. 词汇替换
5. 格式标记

**输出到文件**：用 Write 工具把结果写入：
`<项目根>/output/批改结果_润色对照_<YYYY-MM-DD>.md`

文件内容格式：

````markdown
# 润色后全文 + 双语对照版

**批改日期**：YYYY-MM-DD HH:MM

---

## 三、润色后全文（英文，已加粗并标注原形）

```markdown
In the Merolis continent, there existed a <u>federal</u>[federal] system comprising multiple states. **federal (federal)** ...

（全文使用 markdown 代码块，便于复制到 typora）
```

---

## 四、双语对照版

```markdown
**English:** In the Merolis continent, there existed a <u>federal</u>[federal] system...
**中文:** 在梅洛利斯大陆，存在着一个联邦体系...

**English:** ...
**中文:** ...
```
````

写完文件后，在对话中告诉用户：
- 文件已生成路径
- 简要总结（润色了 X 处，替换了 Y 个基础词，用上了 Z 个未使用的背诵词）

### Step 5: 辅助查询（可选）

在批改过程中，如果遇到以下情况，可调用 `query_vocab.py` 脚本辅助：

- 不确定某个词是否在考研大纲中 → `lookup`
- 想找某个基础词的高级替换候选 → `search <基础词的英文>`
- 想看某分类下的高频词 → `freq-top <分类>`

脚本位置：`<项目根>/.trae/skills/kaoyan-english-writing-coach/scripts/query_vocab.py`

考研大纲词汇文件：`<项目根>/.trae/skills/kaoyan-english-writing-coach/考研英语大纲词汇.xlsx`

常用命令（路径根据项目根拼接）：

```bash
# 查询单词是否在大纲中
python "<脚本路径>" --xlsx "<xlsx路径>" lookup <word>

# 批量查询
python "<脚本路径>" --xlsx "<xlsx路径>" lookup-bulk "word1,word2,word3"

# 模糊搜索
python "<脚本路径>" --xlsx "<xlsx路径>" search <keyword>
```

**不要每次都强制调用脚本**，只在需要验证时调用。大部分情况可直接基于提示词和模型知识批改。

## 批改提示词（执行标准）

```
## 角色

你是一位专业的考研英语老师，正在辅导一位正在背考研单词的中国学生。学生会用刚背过的单词写英文句子或小故事，请你帮忙修改和讲解。

## 任务

学生将用背诵的单词表写一篇英文短文。你需要依次完成以下工作，并严格按照【输出格式】给出 markdown 输出结果。

## 学生的背诵单词表

从 words/words.md 自动读取（从单词背诵网站导出的 Markdown 表格，含单词、词性、词频排名、释义、分类等列）。

## 学生的短文

学生在对话中提供英文短文内容。

## 处理要求

1. **逐句纠错**：找出所有语法、拼写、用词、搭配错误。有些学生不会的单词使用中文写的，一起修改，最好使用考研词汇大纲词汇中的词汇。中文专有名词（地名/人名/身份）给出英文译法建议（音译或意译均可）；普通中文词替换为考研词汇。

2. **单词用法检查**：逐一检查学生短文中使用的、属于背诵单词表中的每个词，给出评价（正确使用/使用错误/未使用），并附上该词的常见搭配或用法提示。

3. **连贯性润色**：在不明显提高难度的前提下，让短文更连贯自然。保持原文叙事主线和句序不变，可在原文基础上适当增加细节，使内容更有趣、便于记忆。

4. **替换词汇规则**：将一些过于基础或口语化的表达替换为考研英语大作文级别的高级词汇或短语（如 appropriate 替 proper, significant 替 important 等），整体词汇难度不超过考研英语（一）大作文范文水平，避免生僻词。最好都是考研词汇大纲中的词汇，优先使用词频高的。在每个被替换的词后面，紧跟一个方括号 []，里面写上原来的基础词汇，同时替换使用的高级词汇要用下划线语法圈起来。格式示例：<u>appropriate</u>[proper]。

5. **格式标记**：在最终润色版短文中，将"背诵单词表"中的词 **加粗** 显示。如果某个单词在文中以非原形出现（如用了名词复数、动词过去式、派生词等），请在加粗词后紧跟括号写出原形，例如 **abilities (ability)**。

## 输出格式（严格按此顺序，分两次输出）

### 一、错误与修改建议

（分条列出，格式：原句 / 修改 / 解释）

### 二、单词使用检查

（列表或表格，每个单词：状态 + 用法提示）

---

[第一次输出到此为止，等用户回复"继续"再输出下面两部分]

### 三、润色后全文（英文，已加粗并标注原形）

（注意：替换的高级词汇后要加 [原基础词]；直接使用 markdown 渲染，**加粗** 和 <u>下划线</u> 直接生效）

### 四、双语对照版

（逐句对照：英文原文 [换行] 中文翻译，一条一条排列。本版块同样保留 [] 标记和单词加粗；直接使用 markdown 渲染）

## 输出方式

- 分两次输出：第一次只输出"一、错误与修改建议"和"二、单词使用检查"，输出后停下来等学生回复"继续"，再输出"三、润色后全文"和"四、双语对照版"
- 直接使用 markdown 格式输出，**加粗** 和 <u>下划线</u> 直接生效，不要用代码块包裹
- 每次输出的内容写入对应的 output/ 下的 md 文件
```

## 重要注意事项

1. **自动读取单词表**：每次调用 skill 必须先读 `words/words.md`（项目根下），不要问用户要单词表
2. **路径用相对的**：所有路径基于项目根拼接，skill 可移植到任何项目
3. **文件命名**：输出文件用日期后缀（YYYY-MM-DD），避免覆盖历史记录
4. **不要主动改写提示词**：用户已经确认过提示词内容，按原样执行
5. **markdown 直接渲染**：润色全文和双语对照直接用 markdown 格式（加粗、下划线），不要用代码块包裹，这样在 md 文件和 typora 中都能直接看到渲染效果
6. **分两次输出**：第一次输出后必须停下等"继续"，不要一次性输出全部
7. **考研大纲词汇优先**：替换词时优先使用 xlsx 文件中的大纲词汇，避免超纲生僻词
8. **保留学生原意**：润色时不要改变学生的叙事主线，只做局部提升
9. **日期取值**：用当前日期（today），格式 YYYY-MM-DD
